# Ember DINOv2 RGB8 input contract

`crates/segment/src/dinov2_input.rs` accepts row-major, interleaved, sRGB encoded RGB8. It returns F32 `[1, 3, side, side]` in channel-first order for `DinoV2::forward`.

The pinned upstream source is [DINOv2 `transforms.py` at commit `7764ea0f912e53c92e82eb78a2a1631e92725fc8`](https://raw.githubusercontent.com/facebookresearch/dinov2/7764ea0f912e53c92e82eb78a2a1631e92725fc8/dinov2/data/transforms.py). Its evaluation preset specifies bicubic `Resize`, `CenterCrop`, tensor conversion, and ImageNet normalization (`mean = [0.485, 0.456, 0.406]`, `std = [0.229, 0.224, 0.225]`).

`Small224` is official: short edge 256, center crop 224. `Large518` uses short edge 592 and crop 518 at same ratio; it is experimental because upstream evaluation preset is 224.

For bounded work, input width and height must be nonzero, each ≤ 16,384, pixel count ≤ 32,000,000, and `rgb.len()` must equal `width × height × 3` exactly. Output allocation is capped by 3 × 518² F32 values; F64 accumulation is the same fixed pixel count, and each widened filter has at most 257 taps under these limits. Resize dimensions use integer floor for long edge, with the selected short edge exact; center crop offset uses integer floor.

Resampling is direct, separable cubic convolution, so a very wide or tall image never allocates its potentially huge intermediate resize. Source coordinates use half-pixel centers: `(resized_index + 0.5) × source_size / resized_size − 0.5`. The kernel uses Pillow's bicubic coefficient `A = -0.5`; when downsampling, its 2-pixel support is widened by `source_size / resized_size`, so high-frequency detail is antialiased rather than sampled from four fixed taps. Source bounds are clipped, then coefficients are normalized at each edge. Horizontal rows are filtered once and accumulated into output rows, keeping memory bounded by input-row coverage, one output row, and the fixed output tensor. Each result is rounded to nearest Rust `f64::round` semantics, clamped to `0..=255`, divided by 255, then normalized per channel. Generated values are checked finite before Candle tensor creation; RGB8 input itself cannot contain NaN or infinity.

Pillow 12.3.0's [pinned upstream resampling implementation](https://github.com/python-pillow/Pillow/blob/12.3.0/src/libImaging/Resample.c) was used as a behavioral reference for widened support and edge normalization; no Pillow source is copied here. This is an explicit Ember numerical contract, not a claim of Pillow or torchvision byte-for-byte parity. Their coefficient quantization, intermediate 8-bit rounding, backend coordinate rounding, and crop/resize dimension rounding can differ. Before model qualification, run a reference gate against the pinned DINOv2 Python pipeline on synthetic ramps, impulses, constant channels, odd aspect ratios, downsampling patterns, and boundary-heavy images; record maximum per-channel absolute error and agree a tolerance. Keep any reference fixtures outside this source tree.
